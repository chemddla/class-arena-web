# 🌍 반 협동 레이드 (레이드) 설계안

반 전체가 한 주 동안 거대 보스 한 마리의 체력을 같이 깎는 컨텐츠. 혼자 싸우지만 피해는 반 전체가 공유하는 보스 체력에서 빠지고, 보스가 쓰러지면 반 전원이 보상을 받는다.

## 1. 핵심 규칙

| 항목 | 내용 |
|---|---|
| 주기 | 월요일 00:00 새 보스 등장, 일요일 23:59까지 (주차 키 `2026-W45` 형식) |
| 보스 | `ELITE_BOSS_DEFS`의 20마리를 반 진행 단계(`stage`)대로 씀. 처치하면 다음 주는 다음 단계, 못 잡으면 같은 단계 다시 |
| 체력 | 반 공유. `maxHp = 보스 기본 hp × 반 학생 수 × WORLD_BOSS_HP_PER_STUDENT` (계수는 밸런스 시뮬로 정함, 교사가 관리 탭에서 ×0.5~×3 조절 가능) |
| 도전 | 하루 3회 (`dailyRewards.worldBossTries`), 혼자 용병 8명(`RAID_PICK`)으로 180초(`ELITE_RAID_TIME_LIMIT_SEC`) 또는 전멸까지 |
| 피해 반영 | 전투가 끝나면 파란 팀 `damageDealt` 합계를 서버 체력에서 transaction으로 차감 |
| 처치 | 체력이 0이 되는 순간 그 전투의 주인이 "마지막 일격". 처치하면 그 주에 바로 다음 단계 보스가 등장(주 2마리 이상 가능) |
| 광폭화 | 남은 체력 30% 이하면 공격력 ×1.3, 붉은 빛(탑 하드모드 표시 재활용) → 막판 긴장감 |
| 스킬 | `ELITE_BOSS_SKILLS` 7개 전부 열림 (단계 무관) |

도전 중 보스 체력은 **도전 시작 시 읽은 값**으로 시작한다. 두 명이 동시에 마지막 피해를 주면 transaction 순서대로 먼저 0을 만든 사람이 처치자가 된다.

## 2. 보상

| 때 | 누구 | 보상 |
|---|---|---|
| 도전 1회 끝날 때 | 본인 | 준 피해에 비례한 CA (`피해 / maxHp × 보스 rewardMc × 2`, 1회 상한 보스 rewardMc의 20%) + 수호 PT 8 |
| 처치 순간 | 반 전원 (기여 0이어도) | 보스 `rewardMc` × 0.5 |
| 처치 순간 | 기여도 1·2·3위 | rewardMc × 1.0 / 0.6 / 0.4 추가 |
| 처치 순간 | 마지막 일격 | rewardMc × 0.3 추가 + 칭호 "🗡️ 마무리 영웅" (그 주 동안 이름 옆) |
| 주 마감 | 기여도 1위 | 명예의 전당에 "이번 주 토벌 MVP"로 용병과 함께 전시 |

보상 수령은 기존 `eliteRewardClaimed` 방식처럼 학생 기록(`stu.worldBossClaimed[weekKey]`)을 보고 각자 클라이언트에서 한 번만 받는다. 처치 당시 접속 안 한 학생은 다음 접속 때 "레이드가 쓰러졌어요!" 배너와 함께 받는다.

일일 미션 추가: `worldBoss` "🌍 레이드 도전하기" (goal 1), `worldBoss3` "레이드 3번 도전하기" (goal 3).

## 3. 데이터 (Firebase)

```
classes/{code}/world_boss/
  current: { weekKey, stage, bossId, maxHp, hp, hpMult, startedAt, killedAt, killedBy, killedByName }
  contrib/{weekKey}/{studentId}: { name, dmg, tries, best, lastAt }
  log/{weekKey}/{pushId}: { id, name, dmg, at, kill: true|false }   // 최근 30개만 유지
  history/{weekKey}: { bossId, stage, killed, killedBy, top3: [...] }  // 주 마감 때 current를 복사
```

- 규칙: `raid_rooms`처럼 `meta`가 있으면 쓰기 허용. `current/hp`는 숫자이고 0 이상만 통과.
- 체력 차감과 기여도 합산은 둘 다 `ref.transaction`으로 (이미 `mergeWriteRoom`과 수학 대결에서 쓰는 방식).
- 주차 전환은 **먼저 접속한 클라이언트**가 한다: `current.weekKey`가 지금 주와 다르면 `history`로 옮기고 새 보스를 만든다 (transaction으로 한 명만 성공).
- 교사 관리: `hpMult` 조정, 보스 리셋, 단계 되돌리기.

## 4. 전투 (코드 재활용)

- 새 `sim.mode = 'world_boss'`. 맵은 `ELITE_BOSS_MAPS`의 그 보스 맵.
- 보스는 `buildCenterEliteBoss(bossDef, 1)`를 그대로 쓰되 `overrideMaxHp = current.maxHp`, 시작 체력은 `current.hp` (남은 만큼만 차 있는 체력바가 그대로 보임).
- 파란 팀은 `buildCoopRaidBlueUnits([{ stu, mercs }])` 1인 구성, 왼쪽 진형.
- 종료 조건은 `elite_raid`와 같음(전멸·시간 초과·보스 사망). 결과 정산은 `finishMonsterRush`처럼 `world_boss` 전용 함수에서: 피해 합계 → transaction → 결과창에 "레이드 체력 12,340 깎음 (남은 체력 61%) · 오늘 남은 도전 2회".
- 관전은 기존 `pvp_live` 송출을 그대로 (1인 전투도 관전 가능).

## 5. 화면

**레이드 탭 → "🌍 레이드" 서브탭**
1. 보스 초상 + 이름 + 단계, 거대한 체력 바(`onValue` 실시간), 남은 시간(일·시간)
2. "⚔️ 도전하기 (오늘 2/3)" 버튼 → 기존 레이드 용병 고르기 화면 → 전투
3. 기여도 랭킹 (이름·총 피해·도전 수, 내 순위는 강조)
4. 실시간 피해 로그 ("민수 12,340 피해!", 처치 순간은 금색)
5. 보상 안내 (처치 시 전원 ○○ CA, 상위 3명 추가)
6. 지난 주 기록 (history)

**홈 상단 배너**: "🌍 레이드 [리치] 체력 43% · 3일 남음" 얇은 바. 누르면 서브탭으로. 처치 순간엔 모든 접속자에게 `showRewardBanner`.

## 6. 체력 계수 정하는 법

밸런스 시뮬(대결·탑·보스·엘리트 다 돌리는 기존 방식)에 "학생 평균 로스터 8명 vs 보스 180초"를 추가해서 1회 평균 피해 `D`를 구한 뒤:

```
목표: 반 전원이 하루 2회씩 4일 → 처치
maxHp = D × N × 2 × 4 = 8·D·N  (N = 반 학생 수)
```

전투력 격차가 큰 반을 위해 상위 20% 학생 피해를 2배로 보고 조금 더 올린다. 교사 `hpMult`로 현장 조정.

## 7. 구현 순서 (커밋 단위)

1. 주차 키·데이터 구조·`database.rules.json`·주차 전환 transaction

3. 서브탭 UI(체력 바·랭킹·로그·도전 버튼)와 홈 배너, 실시간 구독
4. 보상(참여·처치·순위·마지막 일격)·칭호·명예의 전당·일일 미션
5. 관리자 조정(hpMult·리셋)과 밸런스 시뮬로 계수 확정, 테스트 전장 `/test`에 보스 추가

## 8. 구현 상태 (2026-11-04)

결정: 처치하면 같은 주에 다음 단계 보스가 바로 나옴 · 하루 3회 · 기여 0이어도 전원 보상.

들어간 것 (`index.html`의 `WORLD_BOSS` 상수와 `WorldBoss` 객체, `sim.mode === 'world_boss'`):
- 주차 키(월요일 날짜)·`world_boss/{current, contrib, log, history}`·규칙·규칙 테스트
- 전투 모드(남은 체력 주입, 스킬 7개, 30% 광폭화, 3분 제한), 정산(transaction 차감·기여도·로그·마지막 일격)
- 레이드 탭 상단 패널(체력 바·기여 랭킹·최근 기록·지난 보스), 모든 탭 위의 띠, 선생님 조정 상자(체력 배율 ×0.5~×3·같은 단계 다시·단계 위아래)
- 참여 보상·처치 전원 보상·기여 1~3위·마지막 일격 보상(접속 안 했던 학생은 다음 접속 때), 일일 미션 2개, 선생님의 도전 횟수 초기화

체력 계수는 `hpPerStudent = 2` (= 엘리트 보스 체력 × 학생 수 × 2, 학생 수는 최소 5로 계산)로 두고 선생님 배율로 맞추는 상태. 밸런스 시뮬로 다듬는 건 아직.

아직 안 한 것: 주간 MVP 명예의 전당 전시, 마무리 영웅 칭호를 이름 옆에 표시, 레이드 전투 관전, 밸런스 시뮬로 체력 계수 확정.

## 9. 바뀐 규칙 (2026-11-04 · 실시간 레이드)

- 이름: 레이드. 전투 아래 따로 [레이드] 탭.
- **용병 1명**만 데리고 참가하고 직접 조종.
- 아무도 없을 때 참가하면 **레이드 방이 열리고** 그 학생이 방장(전투 계산). 방이 열려 있는 동안 다른 친구가 참가하면 **바로 난입**: 방장 화면이 그 친구 용병을 전장에 넣고, 친구 화면은 실시간 팀전처럼 방장 화면을 받고 조작만 보냄. 방이 열리면 다른 친구들에게 알림, 띠·탭에 "🔴 진행 중 · 난입 가능".
- `world_boss/room`: `{ id, key, hostId, hostName, startedAt, hb, members: { 학생id: { name, merc, at } } }`. 방장이 4초마다 `hb`를 갱신, 15초 넘게 없으면 끝난 방.
- **하루 1번** (들어가는 순간 씀, 중간에 나가도 돌려받지 않음).
- 끝나면 방장이 보스가 실제로 잃은 체력을 공유 체력에서 한 번에 빼고 방을 닫음. 학생마다 자기 용병이 준 피해로 참여 보상·기여도. 마지막 일격 = 쓰러질 때 마지막으로 때린 용병의 주인. 처치 보상 순위는 처치 8초 뒤 기여도로 매김.
- 난입한 친구가 나가면 그 친구 용병은 AI가 이어서 싸우고 그 친구만 보상 없음. 방장이 나가면 레이드가 끝나고 친구들은 그때까지의 피해로 정산.
- 밸런스(시뮬): 용병 1명 AI 혼자 2,800~7,300 피해·28~44초 버팀 → 보스 공격력 ×0.2, 체력 = 엘리트 보스 체력 × 학생 수 × 0.2 (12명 기준 1단계 272,160, 매일 다 참가하면 4일쯤). 이미 나와 있던 보스는 남은 비율 그대로 새 체력(`v: 2`).
- 아직: 방장이 끊기면 친구 화면은 '연결이 끊김'으로 끝나고 그 판은 정산되지 않음(방장 넘기기 없음). 레이드 관전 없음.

## 10. 바뀐 규칙 (2026-11-04 · 방장 없는 늘 열린 레이드)

9번의 방장·방 방식은 없앰.
- 레이드는 **늘 열려 있음**. 언제든 용병 1명을 데리고 들어가면 됨 (하루 1번, 3분, 내 용병 직접 조종).
- 참가한 학생마다 **자기 화면에서** [내 용병 vs 보스]를 계산. 보스 체력은 서버 `current.hp` 하나를 같이 씀: 내가 준 피해를 2초마다(끝날 때 한 번 더) transaction으로 빼고, 서버 체력이 줄면(친구가 깎으면) 내 화면 보스 체력도 줄어듦. 내 공격으로 0이 되면 내가 마지막 일격.
- 지금 싸우는 친구 용병은 `world_boss_live/{학생id}`(`n` 이름, `m` 용병, `s` 위치·동작·체력, `at`)를 0.12초마다 올려서 서로의 화면에 함께 그림(계산에는 안 들어감). 5초 넘게 소식이 없으면 나간 것으로 봄. 함께 싸우는 사람이 n명이면 보스 공격력 ÷ √n.
- **아무도 참가하지 않으면 보스는 멈춰 있음** (체력을 깎는 사람이 없음). 띠·탭에 "🟢 N명 싸우는 중" / "⏸ 멈춤", 아무도 없던 레이드에 누가 들어오면 다른 친구들에게 알림.
- 친구가 보스를 쓰러뜨리면 싸우던 모두의 레이드가 승리로 끝나고 다음 단계 보스가 바로 나옴. 나가기는 벌칙 없음(준 피해·참여 보상 그대로).
- 등장 연출(하늘에서 떨어짐)은 엘리트 협동 사냥에만.

## 11. 실시간 동기화 (2026-11-04 · 모두 같은 전투)

10번의 '각자 따로 전투 + 친구 그림만'은 없앰. 이제 참가한 친구 모두가 **같은 전투**를 봄.
- 보이는 방장은 없음. 참가한 학생 중 한 명의 화면이 몰래 **계산 담당**이 되어 전투를 계산하고 실시간 팀전처럼 화면을 보내고, 나머지 친구 화면은 그 화면을 받고 조작만 보냄.
- `world_boss/room`: `{ id, key, bid, ep, owner, hb, members: { 학생id: { name, merc, at, t0, dmg, leave, out } } }`. 계산 담당이 1초마다 `hb`(실제로 계산 중일 때만), 2초마다 깎인 보스 체력을 `current.hp`에 반영하고 친구별 피해를 `dmg`에 적음.
- 들어가면 **3초 뒤 내 용병이 하늘에서 떨어져 착지**(몬스터 러쉬 낙하 연출, 유닛마다 `dropWarn`). 한 사람은 착지 뒤 3분, 용병이 쓰러지거나 나가면 그 사람만 끝남(`done/{key}/{학생id}`에 결과 → 그 친구 화면이 보상을 받고 지움, 창을 닫았으면 다음 접속 때 받음).
- 계산 담당이 끝나면 전투 상태를 통째로(`pvp_live/{방}/handoff`) 가장 먼저 들어온 친구에게 넘김. 계산 담당 화면이 6초 넘게 조용하면(창 닫음·다른 탭) 남은 친구가 자기 화면 상태로 이어받고, 돌아온 옛 계산 담당은 받는 쪽으로 바뀜.
- 보스가 쓰러지면 모두 승리, 마지막으로 때린 용병의 주인이 마지막 일격. 아무도 없으면 계산하는 화면이 없어 보스는 멈춤. 함께 싸우는 사람 n명이면 보스 공격력 ÷ √n.
- 자동 전투/직접 조종은 들어갈 때 고르고(전투는 멈추지 않음) 싸우는 중에도 바꿀 수 있음. 다른 친구 용병은 고를 수 없음.
