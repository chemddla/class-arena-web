# 용병 페이퍼돌 · 베이스 바디(마네킹) 규격서 v0.1

용병 외형을 **마네킹 1개 + 갈아 끼우는 레이어**로 그리기 위한 그림·데이터 규격이다.
그림 작업자와 엔진 코드가 이 문서 하나를 기준으로 맞춘다.

- 기준 그림: 현재 `assets/sprites/merc/*` 24장(4직업 × 외형 6종)에서 잰 비율·동작 구성
- 좌표계: **칸 왼쪽 위가 (0, 0), 오른쪽 +x, 아래쪽 +y**, 단위 px (그림 1픽셀 = 1px)
- 방향: **오른쪽을 보는 3/4 시점만** 그린다. 왼쪽은 엔진이 좌우 반전
- 표시 크기: 기준 키 81px 그림을 전투에서 54px(약 0.67배)로 줄여 그림 (`SPRITE_DRAW_H` 그대로)

> ⚠️ 아직 정하지 않은 것: 그림 제작 방식(직접 도트 / AI 생성 후 보정). 이 문서는 어느 쪽이든 결과물이 지켜야 할 조건만 정한다.

## 1. 칸(셀) 규격

| 항목 | 값 | 비고 |
|---|---|---|
| 칸 크기 | **160 × 100** | 모든 직업·모든 레이어 공통 |
| 발 기준점 (anchorX, anchorY) | **(80, 96)** | 서 있는 발바닥 맨 아래 줄 = y 96 |
| 기준 키 (standH) | **81** | 기본 머리카락 꼭대기 = y 15. 지금 전사·궁수와 같은 배율 |
| 모자 상한 | y 2 | 모자·장식은 y 2까지 허용 (지금 마법사 모자 키 92 → y 4) |
| 좌우 범위 | x 0 ~ 159 | 전사 베기 앞끝 +77, 회전베기 뒤끝 −78이 들어가는 폭 |
| 발 아래 여백 | y 97 ~ 99 | 그림을 그리지 않음 (먼지 등 이펙트는 따로) |
| 초상화 중심 (portraitCX) | 80 | 지금 초상화 자르기 코드 그대로 사용 가능 |

시트 배치:

- 프레임은 **가로 한 줄**로 이어 붙인다. 프레임 i의 왼쪽 위 = (i × 160, 행 × 100)
- 프레임 수는 항상 **31칸** (2장의 공통 프레임 표). 쓰지 않는 칸도 투명하게 비워 두고 칸 수는 유지
- 시트 너비 = 31 × 160 = **4960px** (WebP 최대 16383px 안)
- 몸·옷처럼 앞뒤로 나뉘는 레이어는 **3행**(높이 300px)을 쓴다 → 4장의 깊이 행

### 1-1. 몸 비율 (idle 0번 프레임 기준)

지금 그림의 2등신 꼬마 비율(머리가 키의 약 55%)을 그대로 따른다.

| 부위 | y (칸 좌표) | 지면에서 높이 | x 범위 / 크기 |
|---|---|---|---|
| 기본 머리카락 꼭대기 | 15 | 81 | — |
| 두개골 꼭대기(민머리) | 19 | 77 | 두개골 폭 38px: x 63 ~ 100 |
| 눈 중심선 | 45 | 51 | 눈 5×7px, 앞눈 중심 x 89, 뒷눈 중심 x 77 |
| 입 | 53 | 43 | x 86 ~ 89 |
| 턱 | 58 | 38 | — |
| **목 회전점 (head 관절)** | 59 | 37 | x 82 |
| 어깨선 | 62 | 34 | 어깨 폭 26px: x 68 ~ 93 |
| 허리 | 72 | 24 | — |
| 가랑이 | 79 | 17 | 엉덩이 폭 22px: x 70 ~ 91 |
| 발바닥 | 96 | 0 | 뒷발 x 70 ~ 78, 앞발 x 84 ~ 93 |

- 머리 40px / 몸통 17px / 다리 17px. 머리 폭(38px + 머리카락)이 어깨(26px)보다 넓은 것이 정상
- 모든 동작 프레임에서 **두개골 크기는 변하지 않는다** (머리는 옮기기만 하고 늘리거나 줄이지 않음)
- 0.67배로 줄여 보이므로 **얼굴 요소는 최소 2px 두께**로 그린다 (1px 선은 전투 화면에서 뭉개짐)

## 2. 공통 프레임 표

몸 자세는 직업이 아니라 **동작 세트** 3개로 나눈다. 세트마다 마네킹 시트를 하나씩 둔다.

| 세트 | 쓰는 직업 | 마네킹 시트 |
|---|---|---|
| `melee` | 전사 | `body_melee.webp` |
| `staff` | 마법사, 힐러 | `body_staff.webp` |
| `bow` | 궁수 | `body_bow.webp` |

프레임 번호는 세 세트가 모두 같다.

| 번호 | 동작 (`anims` 키) | 칸 수 | 프레임당 틱 | 내용 | 세트별 차이 |
|---|---|---|---|---|---|
| 0 – 3 | `idle` | 4 | 30 | 숨쉬기 (0·2 기본, 1·3 살짝 내려앉음) | **세 세트 똑같은 그림** |
| 4 – 7 | `walk` | 4 | 8 | 걷기 한 주기 | **세 세트 똑같은 그림** |
| 8 – 9 | `hurt` | 2 | — | 맞고 뒤로 젖힘 | **세 세트 똑같은 그림** |
| 10 – 13 | `death` | 4 | 12 | 휘청 → 무릎 → 쓰러짐 → 누움 | **세 세트 똑같은 그림** |
| 14 – 17 | `attack` | 4 | 6 | 예비 → 휘두름 → 끝 → 복귀 | 베기 / 지팡이 내밀기 / 활 당겨 쏘기 |
| 18 – 21 | `skill` | 4 | 8 | 18 = 시전 유지 자세(`casting`) | 칼 치켜듦 / 지팡이 들어 올림 / 하늘로 겨눔 |
| 22 – 24 | `whirl` | 3 | 5 (반복) | 회전베기 | `melee`만. 나머지 세트는 빈 칸 |
| 25 – 27 | `shout` | 3 | 12 | 함성 | `melee`만 |
| 28 – 30 | `charge` | 3 | 6 (반복) | 돌진 | `melee`만 |

- 0 ~ 13번은 세 세트가 **픽셀까지 같아야** 한다. 옷·머리 레이어도 이 구간은 한 번만 그리면 세 세트에 모두 쓴다
- 무기를 든 손 모양은 0 ~ 13번에서도 세트마다 다를 수 있다 → 손이 아니라 **무기 레이어 + 손 관절 좌표**로 처리 (3장)
- 지금 엔진의 `skillAnims`는 다음처럼 옮긴다: `stun_strike → attack`, `whirlwind → whirl`, `warcry / roar → shout`, `charge → charge`
- 베기 궤적, 회오리 고리, 함성 반짝임, 돌진 잔상, 힐러 후광은 **마네킹·레이어에 그리지 않는다**. 이펙트 아틀라스(`assets/sprites/fx/`)로 따로 그린다

### 2-1. 머리 자세(head pose)

머리에 붙는 레이어(얼굴·머리카락·모자)는 프레임마다 그리지 않고, 자세 4개만 그려서 관절 좌표에 옮겨 붙인다.

| 자세 | 뜻 | 쓰는 프레임 (예) |
|---|---|---|
| `N` | 기본 오른쪽 3/4 | idle, walk, attack, skill 대부분 |
| `T` | 앞으로 숙임 (약 15°) | 공격 휘두름, 돌진, 피격 |
| `B` | 뒤돌아봄 (뒤통수가 보임) | 회전베기 가운데 프레임 |
| `L` | 누움 (머리가 오른쪽 아래로 눕힌 모양) | 쓰러짐 마지막 2칸 |

- 회전으로 만들지 않고 자세마다 **따로 그린다** (도트 회전은 깨짐)
- 표정은 얼굴 레이어의 변형으로 따로 둔다: `normal`, `blink`, `hurt`, `shout`, `ko`

## 3. 프레임별 관절 좌표 JSON

마네킹이 완성되면 그림 작업자가 프레임마다 관절 위치를 적는다. 엔진은 이 값으로 머리·무기·등 장식을 붙인다.

### 3-1. 관절 목록

| 키 | 위치 | 붙는 레이어 | 값 |
|---|---|---|---|
| `head` | 목 회전점 (턱 바로 아래 목 위쪽 가운데) | 얼굴, 머리카락, 모자 | `x, y, pose, expr` |
| `handF` | 앞손 쥐는 점 (주먹 가운데) | 주무기 | `x, y, a, z` |
| `handB` | 뒷손 쥐는 점 | 보조 무기, 방패, 활 몸통 | `x, y, a` |
| `back` | 목 뒤 아래 (망토·화살통 다는 점) | 등 장식 | `x, y` |

- `a`: 무기가 향하는 각도(도). 0 = 오른쪽(앞), 90 = 아래, 180 = 왼쪽(뒤), 270 = 위. 화면 기준 시계 방향
- `z`: 주무기를 몸 앞에 그릴지(`"front"`, 기본) 몸 뒤에 그릴지(`"back"`, 회전베기 뒤쪽 등)
- 관절이 보이지 않는 프레임은 `null` → 그 관절에 붙는 레이어를 그 프레임에서 그리지 않음
- 모든 좌표는 **칸 안의 좌표**(0 ~ 159, 0 ~ 99)이고 정수

- 쓰지 않는 칸(staff·bow의 22 ~ 30번)은 `null`

### 3-3. 아이템(레이어) 정의 파일 `assets/sprites/paperdoll/items.json`

아이템은 그리는 방식에 따라 세 종류다.

| `kind` | 그리는 방식 | 그림 단위 | 예 |
|---|---|---|---|
| `frame` | 마네킹과 같은 31칸 시트를 칸 그대로 겹침 | 세트별 시트 (0 ~ 13번은 공유) | 옷, 바지, 신발, 망토, 시위가 당겨지는 활 |
| `head` | `head` 관절에 머리 자세별 그림을 붙임 | 자세 4개 × (뒤/앞) | 얼굴, 머리카락, 모자, 두건 |
| `hand` | `handF` / `handB` 관절에 각도별 그림을 붙임 | 각도 16방향 (22.5° 간격) | 칼, 지팡이, 방패 |

```json
{
  "spec": "paperdoll-items/1",
  "items": {
    "hair_spiky_01": {
      "slot": "hair", "kind": "head", "src": "assets/sprites/paperdoll/hair_spiky_01.webp",
      "palette": ["hair"],
      "poses": {
        "full":   { "N": { "front": [0, 0, 56, 52, 28, 46], "back": null }, "T": { "...": "..." } },
        "capped": { "N": { "front": [56, 0, 56, 40, 28, 34], "back": null } }
      }
    },
    "hat_wizard_01": {
      "slot": "hat", "kind": "head", "src": "assets/sprites/paperdoll/hat_wizard_01.webp",
      "palette": ["cloth1", "accent"], "hair": "capped",
      "poses": { "N": { "front": [0, 0, 80, 60, 34, 58], "back": [80, 0, 40, 30, 20, 26] } }
    },
    "sword_basic_01": {
      "slot": "weapon", "kind": "hand", "joint": "handF", "src": "assets/sprites/paperdoll/sword_basic_01.webp",
      "palette": ["cloth2", "accent"],
      "angles": { "0": [0, 0, 40, 12, 4, 6], "22.5": [40, 0, 38, 20, 5, 7] }
    },
    "robe_mage_01": {
      "slot": "outfit", "kind": "frame", "palette": ["cloth1", "cloth2", "accent"],
      "src": { "common": "assets/sprites/paperdoll/robe_mage_01.webp", "staff": "assets/sprites/paperdoll/robe_mage_01_staff.webp" }
    }
  }
}
```

- 사각형 표기는 이펙트 아틀라스와 같은 `[x, y, w, h, 붙는점x, 붙는점y]`
  - `head` 종류: 붙는점 = 그림 속 목 회전점
  - `hand` 종류: 붙는점 = 손잡이를 쥐는 점. 각도 0° 그림은 칼끝이 오른쪽을 향하게
- `hand` 종류는 16방향을 다 그리지 않아도 된다. 엔진이 가장 가까운 각도의 그림을 고름 (최소 0 / 45 / 90 / 135 / 180 / 225 / 270 / 315)
- `frame` 종류의 `src`가 문자열이면 31칸을 다 그린 시트 한 장. 객체면 `src.common`은 0 ~ 13번 칸만, `src.<세트>`는 14 ~ 30번 칸만 그린 시트이고, 둘 다 너비는 31칸(4960px)을 유지한다. 그 세트를 지원하지 않는 아이템은 키를 빼고, 엔진은 그 직업에 장착하지 못하게 함
- `hair` 값(모자 전용): `"show"` 머리 그대로 / `"capped"` 머리카락의 `capped` 변형(정수리 볼륨 없음) 사용 / `"hidden"` 머리카락 안 그림
- `hides`: 이 아이템이 숨기는 레이어 목록. 예: 두건 `"hides": ["hair.back"]`

## 4. 레이어 순서

뒤에서 앞으로 그린다. `frame` 종류의 3행 시트는 **0행 = 뒤, 1행 = 가운데, 2행 = 앞**이다.

| 순서 | 레이어 | 종류 | 설명 | 필수 |
|---|---|---|---|---|
| 1 | `cape` 0행 | frame | 망토 뒷자락 | |
| 2 | `hair.back`, `hat.back` | head | 긴 머리 뒷부분, 두건 뒷자락, 모자 챙 뒤쪽 | |
| 3 | `backItem` | — (`back` 관절) | 화살통, 등에 멘 무기 | |
| 4 | `offhand` | hand (`handB`) | 방패, 활 몸통 | |
| 5 | `weapon` (z = back일 때) | hand (`handF`) | 몸 뒤로 넘어간 주무기 | |
| 6 | **마네킹 0행** | 마네킹 | 뒷팔 | ✔ |
| 7 | `outfit` 0행 | frame | 뒷소매 | |
| 8 | **마네킹 1행** | 마네킹 | 몸통·다리·머리(민머리 피부) | ✔ |
| 9 | `legs` | frame | 바지, 치마 | ✔ |
| 10 | `shoes` | frame | 신발 | ✔ |
| 11 | `outfit` 1행 | frame | 상의, 갑옷, 로브 (긴 로브는 신발을 덮어도 됨) | ✔ |
| 12 | `face` | head | 눈, 눈썹, 입 | ✔ |
| 13 | `hair.front` | head | 앞머리, 옆머리 | ✔ |
| 14 | `hat.front` | head | 모자, 투구, 두건 앞 | |
| 15 | `cape` 1행 | frame | 어깨·목 앞으로 넘어온 망토 | |
| 16 | `weapon` (z = front일 때) | hand (`handF`) | 주무기 | |
| 17 | **마네킹 2행** | 마네킹 | 앞팔 (주먹이 무기 손잡이를 덮음) | ✔ |
| 18 | `outfit` 2행 | frame | 앞소매, 장갑 | |

- 무기 → 앞팔 순서라서 손이 손잡이를 감싸 쥔 모양이 된다. 그래서 **앞팔은 반드시 마네킹 2행에 따로** 그린다
- `frame` 종류의 활(시위가 당겨지는 그림)은 `offhand` 자리(4)에 그린다
- 효과는 지금처럼 **다 합친 그림 전체**에 건다 (피격 밝기, 흑화 회색, 레어 금빛 번짐). 엔진은 레이어를 숨은 캔버스에 미리 합쳐 시트 한 장으로 만든 뒤 기존 `drawUnitSprite`로 그린다
- 합칠 때 실제로 그려진 맨 위 줄로 `topH`를 다시 계산한다 (체력바·머리 아이콘 자르기에 사용)

## 5. 팔레트 슬롯

모든 레이어는 아래 **기본색(키 색)으로만** 그린다. 엔진은 색이 정확히 같은 픽셀을 찾아 슬롯 색으로 바꾼다.
지금 외형 6종 대부분이 머리색·옷색만 다르므로, 이 교체만으로 기존 외형을 다시 만들 수 있다.

### 5-1. 그림 규칙

- 투명도는 **0 또는 255만** 쓴다 (반투명 가장자리 금지 → 겹칠 때 번짐이 생김)
- 레이어 하나의 색은 **32색 이하**
- 외곽선: 피부·머리·옷처럼 색이 바뀌는 부위는 그 슬롯의 0번(가장 어두운 색)으로 외곽선을 그린다. 그 밖은 고정 외곽선 색
- 키 색과 같은 색을 다른 용도로 쓰지 않는다 (예: 칼날 회색이 `cloth2` 키 색과 겹치면 칼날까지 바뀜)
- 아이템 고유색(바뀌지 않는 색)은 레이어당 8색까지, 키 색과 겹치지 않게

### 5-2. 슬롯과 기본색

기본색은 지금 `warrior_0`(갈색 머리·빨강 망토·은빛 갑옷)에서 뽑은 색을 기준으로 정했다. 단계는 어두운 색 → 밝은 색.

| 슬롯 | 쓰는 곳 | 0 (외곽선·그늘) | 1 | 2 (기본) | 3 (하이라이트) |
|---|---|---|---|---|---|
| `skin` | 얼굴, 손, 마네킹 피부 | `#8a4838` | `#e0a088` | `#f8d8c0` | `#fff0e4` |
| `hair` | 머리카락, 눈썹 | `#401c14` | `#603428` | `#7a4430` | `#a8704c` |
| `eye` | 눈동자 | `#5a2018` | `#c04838` | — | — |
| `cloth1` | 주색 (망토, 로브, 모자) | `#5a1018` | `#a01c24` | `#d03030` | `#f06050` |
| `cloth2` | 보조색 (갑옷, 안감, 칼날) | `#4c5468` | `#8890a8` | `#c8d0e0` | `#f4f8ff` |
| `accent` | 장식 (금테, 보석, 문양) | `#6a4010` | `#c08020` | `#f8c848` | — |
| `leather` | 가죽 (신발, 벨트, 활) | `#3a2418` | `#6a4428` | `#9a6a40` | — |

바뀌지 않는 고정색:

| 이름 | 색 | 쓰는 곳 |
|---|---|---|
| `outline` | `#1c0c10` | 쇠붙이·고정색 부위 외곽선 |
| `eyeWhite` | `#ffffff` | 흰자, 눈 반짝임 |
| `pupil` | `#100808` | 동공 |

### 5-3. 외형 프리셋 (`palette.json`)

용병마다 슬롯별로 색 묶음을 고른다. 지금의 외형 번호(`skinVariant`)는 아래 프리셋으로 옮긴다. 정확한 색값은 마네킹 시안이 나온 뒤 기존 그림에서 뽑아 채운다.

| 외형 | 전사 | 마법사 | 힐러 | 궁수 |
|---|---|---|---|---|
| 0 | 갈색 머리 · 빨강 망토 | 남색 머리 · 파랑 모자 | 금발 · 흰색·금색 옷 | 주황 머리 · 초록 옷 |
| 1 | 금발 · 파랑 망토 | 은회색 머리 · 진홍 모자 | 연보라 머리 · 남색 옷 | 파랑 머리 · 남색 옷 |
| 2 | 적발 · 진홍 망토 | 민트 머리 · 보라 모자 | 주황 머리 · 초록 옷 | 분홍 머리 · 진홍 옷 |
| 3 | 흑발 · 보라 망토 | 주황 머리 · 검정 모자 | 분홍 머리 · 빨강 옷 | 금발 · 남색 옷 |
| 4 | 녹발 · 초록 망토 | 분홍 머리 · 청록 모자 | 민트 머리 · 청록 옷 | 보라 머리 · 회색 옷 |
| 5 | 은발 · 검정 망토 | 금발 · 초록 모자 | 남보라 머리 · 보라 옷 | 은발 · 검붉은 옷 |

```json
{
  "spec": "paperdoll-palette/1",
  "ramps": {
    "skin":   { "light": ["#8a4838", "#e0a088", "#f8d8c0", "#fff0e4"] },
    "hair":   { "brown": ["#401c14", "#603428", "#7a4430", "#a8704c"], "blond": ["...", "...", "...", "..."] },
    "cloth1": { "red":   ["#5a1018", "#a01c24", "#d03030", "#f06050"], "blue":  ["...", "...", "...", "..."] }
  },
  "presets": {
    "warrior_0": { "items": ["hair_spiky_01", "armor_knight_01", "cape_01", "sword_basic_01"],
                   "colors": { "skin": "light", "hair": "brown", "eye": "red", "cloth1": "red", "cloth2": "silver" } }
  }
}
```

- 피부색도 슬롯이므로 피부 톤 프리셋을 여러 개 둘 수 있다
- 용병 데이터는 `appearance: { items: [...], colors: {...} }`로 저장하고, 기존 `skinVariant`만 있는 용병은 `<직업>_<번호>` 프리셋으로 읽는다

## 6. 검수 기준

새 마네킹·레이어 그림을 넣기 전에 모두 통과해야 한다. 1 ~ 8번은 `tools/check-paperdoll.cjs`가 자동으로 검사하고, 9번은 눈으로 확인한다.

```bash
npm install --no-save --no-audit --no-fund sharp@0.33.5
```

```bash
node tools/check-paperdoll.cjs assets/sprites/paperdoll
```

- 데이터 폴더에 `base.json`, `items.json`이 있어야 하고, 그림 경로는 저장소 루트 기준(`--root`로 바꿀 수 있음)
- 키 색은 `index.html`의 `PD_KEY_RAMPS`를 읽어서 쓰므로 색을 바꿀 때는 그곳만 고친다
- 틀린 곳이 있으면 항목별 위치(칸 번호·행·칸 안 좌표)를 출력하고 종료 코드 1
- 그림은 **PNG 또는 무손실 WebP**로 저장한다. 손실 WebP는 가장자리 투명도와 색이 미세하게 바뀌어 2·3번에서 걸린다

1. 시트 크기: 마네킹은 4960×300, `frame` 종류는 너비 4960에 높이 100·200·300(망토는 2행). `head` / `hand` 종류는 아틀라스라 자유지만 사각형이 그림 안에 있어야 함
2. 투명도 값이 0과 255만 있음
3. 모든 색이 키 색 + 고정색 + 그 아이템 고유색(8색 이하) 안에 있음
4. 마네킹: 서 있는 프레임(idle, walk, attack, skill)에서 땅에 닿은 발의 맨 아래 줄 = y 96
5. 마네킹: idle 0번 두개골 꼭대기 y 19 ±1, 목 회전점 (82, 59) ±1
6. 마네킹·`frame` 레이어: 0 ~ 13번 칸이 세 세트에서 픽셀까지 같음
7. 관절 JSON: 세트마다 프레임 31개, 그려진 프레임에는 `head`가 반드시 있음, 좌표가 칸 안
8. 모든 머리 자세(N·T·B·L)를 겹쳤을 때 머리카락·모자가 두개골 밖으로 빈틈 없이 덮음 (특히 `capped` 머리 + 모자)
   - 자동 검사: 마네킹 1행에서 목 회전점보다 위를 두개골로 보고, 열마다 가장 위 픽셀(누운 자세 `L`은 줄마다 가장 오른쪽 픽셀)이 머리카락 단독, 그리고 `capped` 머리 + 모자 조합마다 덮이는지 확인
9. 이펙트(궤적, 고리, 반짝임)가 몸·옷 레이어에 그려져 있지 않음

## 7. 지금 그림에서 바뀌는 점

- 직업마다 달랐던 칸(156×82, 118×95, 99×90, 120×81)과 기준점이 하나로 통일됨 → `MERC_SPRITE_DEFS`의 직업별 숫자가 사라짐
- 마법사는 지금 기준 키 87로 조금 작게 그리고 있음 → 81로 맞추면 전투에서 약 7% 커 보임. 모자 크기로 조정
- 마법사 대기 동작이 걷기 프레임 재사용에서 전용 4칸으로 바뀜. 힐러 스킬 6칸은 4칸 + 후광 이펙트로 나뉨
- 궁수 대기 동작은 지금 거의 정면 → 오른쪽 3/4로 통일
- 기존 24장은 레이어로 나눌 수 없으므로, 새 마네킹이 나올 때까지 "통짜 레이어"로 감싸 그대로 보이게 둔다

## 8. 합성기 (시제품)

`index.html`의 `getMercSprite` 바로 위, "페이퍼돌 합성기" 블록.

- **켜는 법:** 주소 끝에 `?paperdoll=1`. 없으면 지금과 똑같이 기존 시트를 씀
- **동작:** 외형 하나당 숨은 캔버스(4960×100)에 4장 순서대로 레이어를 합쳐 시트를 만든다. 결과는 `MERC_SPRITE_DEFS` 항목과 같은 필드(`img`, `src`, `cellW`, `anims` …)를 가져서 전투 그리기(`drawUnitSprite`)·초상화 코드를 고치지 않고 쓴다. 초상화용 `src`는 PNG blob 주소
- **비동기:** 처음 찾을 때 합성을 시작하고, 끝나기 전에는 기존 시트를 돌려준다
- **통짜 레이어:** `legacy_<직업>_<번호>` 아이템 24개가 자동으로 등록됨. 기존 프레임을 새 31칸 표에 1:1로 옮김(늘이거나 줄이지 않음). 마법사의 기준 키 87 등 기존 `standH`·`topH`·`portraitCX`는 그대로 이어받아 보이는 크기가 바뀌지 않는다
  - 기존 프레임 수가 모자란 동작은 끝 프레임을 반복해 채움 (끝에서 멈추는 동작이라 결과가 같음)
  - 힐러 스킬 6칸은 staff 세트에서 비어 있는 22 ~ 23번 칸까지 써서 그대로 유지
- **마네킹:** 외형에 `body` 슬롯 아이템이 없으면 `base.json`의 세트별 마네킹 시트를 몸으로 쓰고, `skin` 슬롯 색을 바꿔 그린다
- **새 그림 넣기:** `paperdollRegister({ base, items, ramps })`로 `base.json`·`items.json`·색 묶음을 등록. 외형은 `{ job, layers: [{ item }], colors: { 슬롯: 이름 또는 색 배열 } }`
- **아직 없는 것:** 데이터 파일 자동 불러오기, 용병 데이터의 `appearance` 저장(지금은 `skinVariant` → 통짜 외형만), 합성이 끝났을 때 이미 그려진 초상화 다시 그리기

검증한 것 (브라우저에서 실행):

- 통짜 레이어 24장: 옮긴 모든 칸의 투명도가 원본과 같고, 칸 밖으로 넘친 픽셀 0개. 색값은 반투명 가장자리에서만 최대 ±1 차이(캔버스 내부 반올림, 눈으로 구분 불가)
- 가짜 레이어 그림으로 합성 규칙 확인: 레이어 순서(뒷팔·뒷소매 < 몸 < 옷 < 칼 < 앞팔 < 앞소매), 모자의 `hair: "capped"` 변형 선택, 키 색 교체, 가장 가까운 각도의 무기 그림, `z: "back"` 무기가 몸 뒤로 감, 관절이 `null`인 칸 생략, 옆 칸 넘침 없음, `topH` 계산
