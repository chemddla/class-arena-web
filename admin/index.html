현재 세션 작업 기록

이 브라우저 메모리에만 보관하는 작업 기록입니다. 새로고침하면 사라지며 서버 감사 로그가 아닙니다. 민감한 키 값은 기록하지 않습니다.

① Firebase 연결

Firebase Auth 이메일/비밀번호 로그인과 RTDB REST API를 사용합니다. 외부 SDK와 네트워크 요청은 미리보기 안에서 실행되지 않을 수 있습니다.

인증 토큰은 메모리에만 유지합니다. 새로고침 시 다시 로그인해야 합니다.

② 원본 필드 경로 확인

첨부 HTML에서는 스크립트 본문을 확인하지 못했습니다. 아래 기본값은 추정값이며, 연결 후 학급 상세의 원본 JSON과 대조하여 수정하세요. 중첩 필드는 /로 구분합니다.

기존에 없는 필드는 생성하지 않습니다. 학생 데이터·PIN·교사 키·참여 코드 및 인덱스는 변경하지 않습니다.

실제 서비스 적용 안내

1. 독립 관리자 페이지로 배포

이 HTML을 Firebase Hosting 등 HTTPS 환경에서 서비스하세요. 미리보기는 오프라인 체험용입니다. 원본 게임 파일은 변경하지 않았으며, 이 화면을 만들었다고 실제 프로젝트가 배포되거나 연결된 것은 아닙니다.

2. 총괄 관리자 인증

Firebase Authentication에서 총괄 관리자 계정을 만들고 이메일/비밀번호 로그인을 활성화하세요. 신뢰할 수 있는 서버 또는 Admin SDK에서 해당 UID에 superAdmin: true 커스텀 클레임을 부여해야 합니다. 교사 키나 기본 PIN 1234는 총괄 로그인에 사용하지 않습니다.

3. 보안 규칙을 기존 규칙과 검토·병합

아래는 총괄 전용 최소 예시입니다. 그대로 교체하면 기존 학생·교사 접근이 차단될 수 있습니다. 기존 게임의 인증 구조를 별도로 검토해야 합니다. 상위 경로에 공개 read/write가 있으면 하위에서 이를 취소할 수 없습니다.

{
  "rules": {
    ".read": false,
    ".write": false,
    "classes": {
      ".read": "auth != null && auth.token.superAdmin === true",
      ".write": "auth != null && auth.token.superAdmin === true"
    }
  }
}

이 규칙은 총괄에게 학급 전체 쓰기 권한을 줍니다. 최소 권한 운영을 위해 실제 확인된 수정 필드에만 쓰기를 허용하도록 더 좁히세요. 공개 데이터 아래에 교사 키를 함께 저장하면 마스킹 UI만으로 보호할 수 없습니다.

4. 스키마와 동기화 범위

기본 조회 경로는 원본 화면에 안내된 /classes/{classCode}입니다. 학급명·키·공지·잠금 필드명은 확인되지 않아 설정에서 지정합니다. 기존 필드만 개별 ETag 조건부 PUT으로 수정하여 동시 수정 충돌을 방지합니다. 교사 인덱스, 별도 공지 경로, 메타데이터 복제본은 자동 갱신하지 않습니다. 원본이 다른 경로를 읽는다면 먼저 매핑을 맞춰야 합니다.

5. 운영 시 주의

전체 백업에는 학생 정보와 교사 키 등이 포함될 수 있습니다. 안전한 장치에 보관하고 공유하지 마세요. 삭제·키 재발급·학생 비밀번호 조회는 이 콘솔에서 제공하지 않습니다. REST 실시간 스트림은 취소/권한 오류가 발생하면 종료하며, 버튼으로 다시 연결할 수 있습니다. 브라우저의 클라이언트 기록은 변조 방지 감사 로그를 대신하지 못합니다.
